# Time Tracker — offline-first, written in Haskell

A time-tracking web app for an Android device that spends most of its life
offline. The application logic is Haskell, compiled to WebAssembly by GHC's
wasm backend. There is no server and no runtime network traffic: entries live
in the browser's IndexedDB, and a service worker caches the app shell so it
opens offline after the first load.

## What it does

- **16 large icon buttons** (water, meal, work, coding, exercise, …). Tapping
  one immediately records the current timestamp and what was pressed.
- **Type exact activity** opens an on-screen QWERTY/numeric keyboard, so you
  are never limited to the predefined labels. A hardware keyboard also works.
- **Day view** lists everything logged on a chosen day, newest first, with
  per-entry durations. Use the arrows to browse other days.
- **Edit entries** to change the text or the time; moving the time across
  midnight moves the entry to that day. Entries can also be deleted.
- **Export all data** as CSV for backup.
- Installable as a **PWA** ("Add to Home screen" in Chrome) with a full-screen
  standalone window, app icon and splash background.

The on-device browser is the database. Nothing is sent anywhere; no analytics,
no CDN, no fonts or libraries fetched at runtime.

## Architecture

```
app/Main.hs          All model/UI logic, React-style re-render, event handling.
                     Compiled to a wasm32-wasi reactor with `foreign export javascript`.
web/helpers.js       Thin adapter: DOM nodes, date helpers, IndexedDB, download.
web/app.js           Instantiates the wasm module with WASI + generated JSFFI glue,
                     forwards DOM events to the exported Haskell `onAction`.
web/vendor/wasi.js   Vendored browser WASI implementation (no CDN at runtime).
web/sw.js            Cache-first service worker for full offline operation.
web/dist/            Generated by scripts/build.sh (wasm + JSFFI glue).
scripts/             Build, serve and test scripts.
```

JavaScript never decides anything about the data; it only supplies DOM and
storage primitives. Timestamps come from the device clock (`Date.now()`), so
they are correct even with no connectivity.

## Build

Requires [Nix](https://nixos.org/) with flakes enabled. The flake pins
`ghc-wasm-meta`, which provides the WebAssembly GHC toolchain.

```sh
nix develop
./scripts/build.sh
```

This compiles `app/Main.hs` with `wasm32-wasi-ghc`, runs the JSFFI post-linker,
and writes `web/dist/time-tracking.wasm` plus `web/dist/time-tracking.js`.

## Run locally

```sh
./scripts/serve.sh
# open http://localhost:8000
```

`localhost` is a secure context, so IndexedDB and the service worker both work
during development.

## Install on an Android device

1. Upload the contents of `web/` to any static HTTPS host (GitHub Pages, a
   local NAS with TLS, etc.). The device only needs to reach it **once**.
2. Open the URL in Chrome on the device and choose **Add to Home screen**.
3. Launch from the home-screen icon. The service worker has cached every file;
   from then on the app works with the network switched off and all entries
   are stored locally.

You can also keep it entirely local by running an HTTPS server on the device
(e.g. Termux) and installing the PWA from there, or by bundling `web/` as the
assets of an Android WebView app. The build output is completely static.

If you change the app, bump the `CACHE` name in `web/sw.js` so existing
installations pick up the new shell.

## Tests

```sh
nix develop .#test --command node scripts/test-node.mjs      # logic + FFI in Node
nix develop .#test --command node scripts/test-browser.mjs   # real Chromium + offline reload
```

The browser test starts a temporary local server, drives the compiled wasm
module through taps, keyboard entry, editing and deletion, then switches the
network off, reloads and confirms the data is still there.

## Customising

- **Icons**: edit the `icons` list in `app/Main.hs` (key, glyph, label). The
  day view and CSV export follow it automatically.
- **Keyboard layout**: `letterRows` / `numberRows` in `app/Main.hs`.
- **Theme**: colours are CSS variables at the top of `web/style.css`.
- **Cache version**: `CACHE` in `web/sw.js`.

## Notes

- Timestamps are milliseconds since the Unix epoch, formatted in the device's
  local timezone. Editing a time uses the selected day as the date.
- IndexedDB is durable storage on the device; clearing browser site data will
  erase entries, so use **Export all data (CSV)** periodically.
- GHC's WebAssembly backend is still a technology preview; the flake pins a
  known-good toolchain revision via `flake.lock`.
