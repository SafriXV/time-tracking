# Time Tracker — offline-first, written in Haskell

A time-tracking app for an Android device that spends most of its life offline.
The application logic is Haskell, compiled to WebAssembly by GHC's wasm backend.
There is no server and no runtime network traffic: entries live in IndexedDB,
and a service worker caches the app shell so the web build opens offline after
the first load. The Android APK bundles the whole app, so it is offline from the
very first launch.

## What it does

- **16 large icon buttons** (Eat, Dishes, Clean, Call, Socialize, Read, Coding,
  Sleep, Plan, Journal, Check socials, Dailies, laundry, fold clothes, write blog
  post, shower). Tapping one immediately records the current timestamp and what
  was pressed.
- **Exact activity entry uses the native Android keyboard.** Tap the ⌨ tile (or
  an entry in Day view) and the system keyboard opens on a real text field — no
  custom on-screen keyboard, so swipe typing, autocorrect and your preferred
  keyboard app all work.
- **Day view** lists everything logged on a chosen day, newest first, with
  per-entry durations. Use the arrows to browse other days.
- **Edit entries** to change the text or the time; moving the time across
  midnight moves the entry to that day. Entries can also be deleted.
- **Export all data** as CSV for backup. In the APK it goes straight to
  `Downloads/`; in the browser it downloads normally.
- Installable as a **PWA** ("Add to Home screen" in Chrome), or as a real
  launcher app via the bundled **Android APK**.

Nothing is sent anywhere; no analytics, no CDN, no fonts or libraries fetched at
runtime.

## Architecture

```
app/Main.hs          All model/UI logic, React-style re-render, event handling.
                     Compiled to a wasm32-wasi reactor with `foreign export javascript`.
web/helpers.js       Thin adapter: DOM nodes, date helpers, IndexedDB, downloads.
web/app.js           Instantiates the wasm module with WASI + generated JSFFI glue,
                     forwards DOM events to the exported Haskell `onAction`.
web/vendor/wasi.js   Vendored browser WASI implementation (no CDN at runtime).
web/sw.js            Cache-first service worker for the PWA.
web/dist/            Generated by scripts/build.sh (wasm + JSFFI glue).
android/             Android WebView shell that bundles web/ as assets.
scripts/             Build, serve, test and APK packaging scripts.
```

JavaScript never decides anything about the data; it only supplies DOM and
storage primitives. Timestamps come from the device clock (`Date.now()`), so
they are correct even with no connectivity.

## Build the web app

Requires [Nix](https://nixos.org/) with flakes enabled. The flake pins
`ghc-wasm-meta`, which provides the WebAssembly GHC toolchain.

```sh
nix develop
./scripts/build.sh
./scripts/serve.sh        # http://localhost:8000 (a secure context)
```

## Build the Android APK

The latest prebuilt APK is available on the
[Releases page](https://github.com/SafriXV/time-tracking/releases/latest) —
download `time-tracking.apk` and open it on your phone.

To build it yourself:

```sh
nix develop .#android --command ./scripts/build-apk.sh
```

This rebuilds the wasm, copies `web/` into
`android/app/src/main/assets/web/`, runs Gradle and writes:

```
release/time-tracking.apk
```

The APK uses `androidx.webkit.WebViewAssetLoader` to serve the assets from the
secure origin `https://appassets.androidplatform.net/assets/web/`. That gives
IndexedDB, the service worker and `crypto.randomUUID()` a proper secure origin
without Google Play Services or any network connection.

Install it with:

```sh
adb install -r release/time-tracking.apk
```

or copy the APK to the phone and open it in a file manager. The app is signed
with the standard Android debug key, which is enough for sideloading; if you
want to distribute it, replace that with your own release signing key.

### Why an APK instead of a WebAPK?

On Android, Chrome (with Google Play Services) and Samsung Internet are the only
browsers that install a PWA as a real WebAPK. Open-source browsers available on
F-Droid (Cromite, Brave, Vanadium, Fennec, …) only add a browser-badged shortcut.
This APK is fully FOSS and depends only on the Android system WebView, so it
gives a genuine launcher entry with no proprietary dependencies.

## Host on GitHub Pages

The static PWA lives on the `gh-pages` branch:

**https://safrixv.github.io/time-tracking/**

To refresh it after changing the app:

```sh
# bump CACHE in web/sw.js first so existing installs pick up the new shell
nix develop --command ./scripts/build.sh
git add -A && git commit -m "update app"
git push
git subtree push --prefix web origin gh-pages
```

If you change the app, bump the `CACHE` name in `web/sw.js`.

## Tests

```sh
nix develop .#test --command node scripts/test-node.mjs      # logic + FFI in Node
nix develop .#test --command node scripts/test-browser.mjs   # real Chromium + offline reload
```

The browser test starts a temporary local server, drives the compiled wasm
module through taps, native-text-field entry, editing and deletion, then
switches the network off, reloads and confirms the data is still there.

## Customising

- **Icons**: edit the `icons` list in `app/Main.hs` (key, glyph, label).
- **Input field**: `web/index.html` (`#kb-form` / `#kb-text`).
- **Theme**: colours are CSS variables at the top of `web/style.css`.
- **Cache version**: `CACHE` in `web/sw.js`.

## Notes

- Timestamps are milliseconds since the Unix epoch, formatted in the device's
  local timezone. Editing a time uses the selected day as the date.
- IndexedDB is durable storage on the device; clearing app/browser site data
  will erase entries, so use **Export all data (CSV)** periodically.
- GHC's WebAssembly backend is still a technology preview; the flake pins a
  known-good toolchain revision via `flake.lock`.
- ZWJ emoji sequences (e.g. 🧑‍🤝‍🧑) cannot appear in Haskell string literals; use a
  single code point instead (e.g. 👥).
